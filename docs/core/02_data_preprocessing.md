# 2. Data Preprocessing (Tiền xử lý dữ liệu)

Tài liệu này hiện chỉ giữ ở mức outline. Nội dung chi tiết sẽ được bổ sung sau khi parser, schema trung gian và pipeline annotation MVP được chốt.

## 2.1 Mục tiêu

- Đọc và kiểm tra file genome/SNP đầu vào.
- Giữ lại dữ liệu gốc để truy vết.
- Chuẩn hóa tối thiểu các trường `rsid`, `chromosome`, `position`, `genotype`.
- Ghi nhận genome build nếu file có metadata.
- Chuẩn bị dữ liệu cho ANNOVAR/InterVar clinical annotation, API enrichment bằng MyVariant.info, MyGene.info, ClinPGx/PharmGKB API và optional validation bằng OpenCRAVAT/Ensembl VEP.

## 2.2 Input dự kiến

- File 23andMe/PGP dạng raw text.
- File CSV/TSV có cấu trúc tương tự `rsid`, `chromosome`, `position`, `genotype`.
- VCF nếu pipeline cần mở rộng.

## 2.3 Các bước preprocessing chính

- Detect format và delimiter.
- Bỏ qua comment/header lines.
- Chuẩn hóa tên cột.
- Tách metadata của sample khỏi bảng variants.
- Ghi lại build gốc, ví dụ build36/hg18 trong file PGP `hu43860C`.
- Flag các dòng không phải rsID, missing genotype, duplicate rsID, chromosome đặc biệt (`X`, `Y`, `MT`).

## 2.4 Hướng xử lý genome build

- Không tự coi tọa độ build36 là hg19/hg38.
- Human assembly build 37 tương ứng với GRCh37/hg19 trong hầu hết tool hiện tại. Khi chạy OpenCRAVAT với input build37, dùng `-l hg19`, không dùng `-l hg38`.
- Với MVP, ưu tiên lookup theo `rsID` để giảm rủi ro sai tọa độ.
- Khi dùng OpenCRAVAT, phải ghi rõ input assembly và lưu lại số dòng lỗi converter/mapping.
- Với OpenCRAVAT, reference genome cho converter/mapper nên được quản lý bằng module OpenCRAVAT. Máy hiện tại đã có `hg19wgs` và `hg38wgs` trong `C:\open-cravat\modules\commons`, nên không cần tự tải GRCh37 FASTA/2bit chỉ để chạy converter.

Nếu thiếu module reference của OpenCRAVAT, kiểm tra và cài bằng:

```powershell
oc module ls -a
oc module install hg19wgs
```

Nếu cần reference genome ngoài OpenCRAVAT cho tool khác, có thể tải GRCh37/hg19 từ nguồn chính thức như NCBI Genome Reference Consortium hoặc UCSC `hg19`. Tuy nhiên, với MVP dashboard, ưu tiên dùng module/tool-managed reference để tránh lệch naming convention, contig set và build version.

## 2.5 Note về delimiter và 23andMe-style input

Không phải file nào có cột `rsid,chromosome,position,genotype` cũng chạy thẳng được với OpenCRAVAT `23andme-converter`.

Quan sát local converter:

- `23andme-converter` đọc line bằng tab delimiter, không phải comma CSV.
- Converter chỉ auto-detect header 23andMe chuẩn có câu `This data file is generated by 23andMe.`
- File Kaggle `genome_zeeshan_usmani.csv` là comma-separated CSV, header dạng `# rsid,chromosome,position,genotype`, nên cần convert sang TSV và force input format.

Script chính thức để convert consumer CSV/TSV sang TSV 23andMe-style:

```powershell
python src\preprocessing\convert_consumer_genome.py `
  data\raw_inputs\kaggle_family\genome_zeeshan_usmani.csv `
  data\processed\opencravat\kaggle_zeeshan_usmani\genome_zeeshan_usmani_23andme.tsv
```

Kết quả test script với `genome_zeeshan_usmani.csv`:

- Input rows: `610,544`
- Output rows: `610,544`
- Skipped rows: `0`

OpenCRAVAT command cho file Kaggle build37/hg19:

```powershell
oc run data\processed\opencravat\kaggle_zeeshan_usmani\genome_zeeshan_usmani_23andme.tsv `
  -d data\processed\opencravat\kaggle_zeeshan_usmani `
  -n zeeshan_23andme_hg19 `
  --user-email-opt-out `
  --cleanrun `
  -l hg19 `
  -t text excel `
  --debug `
  -i 23andme
```

Nếu OpenCRAVAT báo `no such table: info` sau converter failure, coi đó là output SQLite incomplete/corrupt từ run fail. Xóa hoặc chạy lại với `--cleanrun`, output folder có sẵn, đúng `-l hg19`, đúng `-i 23andme`, và đúng delimiter TSV.

## 2.6 Hướng ANNOVAR / InterVar cho MVP

ANNOVAR có hai đường input phù hợp với MVP:

- `avinput`: format riêng của ANNOVAR, tối thiểu gồm `chromosome`, `start`, `end`, `reference_allele`, `alternative_allele`.
- `rsID` list: dùng `convert2annovar.pl -format rsid` để map rsID qua dbSNP local thành `chr start end ref alt rsID`.

Điểm quan trọng: consumer SNP file có `rsID` và `genotype`, nhưng ANNOVAR/InterVar làm việc ở mức variant/ref-alt. Vì vậy preprocessing phải giữ bảng gốc để join genotype ngược lại sau annotation.

Flow đề xuất:

```text
23andMe / PGP / Kaggle file
  -> parse rsID, chromosome, position, genotype, build
  -> preserve original_variants table: rsID -> genotype/user/sample/build
  -> extract curated rsID list hoặc clinically relevant subset
  -> convert2annovar.pl -format rsid với dbSNP build phù hợp
  -> generate ANNOVAR avinput: chr start end ref alt rsID
  -> run ANNOVAR annotation
  -> run InterVar clinical classification
  -> join genotype back by rsID + variant coordinate where possible
  -> normalize findings for dashboard/chatbot
```

MVP nên test theo 2 phase:

| Phase | Input | Mục tiêu |
| --- | --- | --- |
| Phase 1: curated rsID clinical demo | 20-50 rsID gồm `rs6025`, `rs3093017`, `rs12562034`, ClinVar pathogenic/likely pathogenic variants và PGx variants | Chứng minh core clinical annotation/classification chạy được, output parse được. |
| Phase 2: consumer SNP upload subset | File 23andMe/PGP/Kaggle đã parse, chọn subset có clinical/PGx/research relevance | Chứng minh pipeline giữ được genotype context và chạy được trên user-style input. |

Caveats bắt buộc ghi nhận:

- Một `rsID` có thể map ra multiple variant records/multiple genomic positions.
- Genome build phải match dbSNP/ANNOVAR database, ví dụ hg19 hoặc hg38.
- Genotype từ consumer file phải được join lại sau annotation; nếu không sẽ mất user-specific context.
- InterVar classification không thay thế expert review.
- Variant không convert được cần fallback bằng MyVariant.info/ClinGen Allele Registry/dbSNP API hoặc bỏ vào unresolved queue.

## 2.7 Nên cài/tải gì cho MVP

### Quyết định hiện tại: test ANNOVAR + InterVar làm candidate clinical backbone

Sau khi xem ANNOVAR input docs, hướng MVP nên ưu tiên test **ANNOVAR + InterVar** vì có thể đi từ `rsID` list hoặc `avinput` mà không cần ép full consumer SNP file sang VCF.

Nên chuẩn bị:

- ANNOVAR local CLI.
- ANNOVAR humandb/database đúng build cần test, ưu tiên hg19/GRCh37 cho consumer SNP build37.
- dbSNP database tương ứng với build để `convert2annovar.pl -format rsid` map được rsID.
- InterVar local CLI và dependency database theo hướng dẫn của InterVar.
- Curated rsID test set 20-50 variants để chạy trước full file.

Không nên bắt demo xử lý full genome ngay từ đầu. Test curated rsID trước để kiểm tra install, output format, clinical classification và join genotype.

### OpenCRAVAT: không phụ thuộc local annotator modules

Sau khi thử cài OpenCRAVAT annotator modules, team quyết định không dùng OpenCRAVAT local annotator modules làm backbone. API-first annotation/enrichment được giữ làm fallback/enrichment path, còn hướng clinical backbone mới cần test là ANNOVAR + InterVar. Lý do bỏ dependency OpenCRAVAT annotator modules:

- OpenCRAVAT converter có thể chạy được để validate file-level flow, nhưng annotator module install dễ treo hoặc kéo dependency lớn.
- Full `clinvar` có xu hướng kéo dependency rất lớn như full `dbsnp` (~52.8 GB).
- `clinvar_acmg` nhẹ hơn nhưng quá trình install cũng bị treo trong lần test hiện tại.
- `pharmgkb`, `gwas_catalog`, `litvar` từng cài được nhưng đã uninstall vì team quyết định không phụ thuộc local OpenCRAVAT modules cho MVP.

Vì vậy, MVP không nên bắt người chạy demo phải cài local annotator database của OpenCRAVAT. OpenCRAVAT chỉ giữ vai trò optional local validation/experiment.

### OpenCRAVAT modules tối thiểu nếu vẫn muốn validate file-level flow

Nếu muốn chạy OpenCRAVAT chỉ để kiểm tra converter/mapper/report export, cần các module nhỏ:


Máy hiện tại đã có `23andme-converter`, `hg19wgs`, `hg38wgs`, `textreporter`, `excelreporter`, `vcf-converter`, nên không cần tải lại trừ khi setup máy mới.

### Không cài OpenCRAVAT annotator modules cho MVP demo

Các module dưới đây không nên là requirement của MVP demo:

- `clinvar`
- `clinvar_acmg`
- `pharmgkb`
- `gwas_catalog`

Nếu sau này cần benchmark local annotation, cài trong nhánh experiment riêng và ghi rõ disk/time/dependency. Không đưa vào setup path chính của MVP.

### Modules chưa nên tải ở MVP

Tránh tải các module rất lớn ở giai đoạn MVP trừ khi thật sự cần:

| Module | Size quan sát | Lý do chưa ưu tiên |
| --- | ---: | --- |
| `dbsnp` | ~52.8 GB | Full dbSNP quá lớn; MVP có thể dùng `rsID` + MyVariant.info/dbSNP web/API hoặc `dbsnp_common`. |
| `dbsnp-converter` | ~30.4 GB | Không cần cho consumer SNP file nếu đã có `23andme-converter`. |
| `gnomad` | ~17.4 GB | Hữu ích nhưng nặng; MVP có thể lấy frequency qua MyVariant.info hoặc chỉ cài sau. |
| `gnomad3` | ~44.0 GB | Quá nặng cho MVP. |
| `gnomad4` | ~23.3 GB | Quá nặng cho MVP ban đầu. |
| `cadd` | ~86.6 GB | Functional score lớn, không phải core clinical interpretation. |
| `cadd_exome` | ~6.8 GB | Nhẹ hơn CADD full nhưng vẫn để optional. |
| `alphamissense` | ~4.0 GB | Useful supporting evidence, chưa cần cho MVP demo. |
| `alfa` / population-specific ALFA modules | ~19-24 GB/module | Quá nặng; chưa cần nếu đã có fallback frequency source. |
| `allofus250k` | ~150.7 GB | Quá lớn cho MVP. |

### API enrichment chính cho MVP

Các nguồn nên dùng API thay vì tải local trong MVP:

- MyVariant.info: variant-level fallback/enrichment theo `rsID`.
- MyGene.info: gene-level enrichment sau khi đã map ra gene.
- MyChem.info: drug/chemical enrichment nếu PGx report cần drug metadata.
- ClinPGx/PharmGKB API: PGx-specific lookup cho drug-response context.

### Mock input nên tải/chọn

Nếu mục tiêu là MVP ít lỗi vặt, ưu tiên tải hoặc dùng:

1. Raw 23andMe file chuẩn build37/hg19, tab-delimited, có header gốc.
2. Raw AncestryDNA file chuẩn nếu đã cài `ancestrydna-converter`.
3. VCF chuẩn GRCh37 hoặc GRCh38 có `REF/ALT` rõ nếu muốn test pipeline bioinformatics sạch.

Không nên tải manual GRCh37 FASTA/2bit chỉ để chạy OpenCRAVAT converter nếu `hg19wgs` đã installed. Nếu cần reference ngoài OpenCRAVAT cho tool khác, dùng NCBI GRC GRCh37 hoặc UCSC `hg19`, nhưng phải ghi rõ naming convention và build.

## 2.10 Chọn mock input để MVP ít lỗi vặt

Best case cho MVP/demo:

- File 23andMe/Ancestry raw export chuẩn, có header metadata rõ ràng, delimiter đúng format tool support.
- Genome build rõ, ưu tiên build37/GRCh37/hg19 nếu dùng consumer SNP data phổ biến.
- Có đủ cột `rsid`, `chromosome`, `position`, `genotype`.
- Có genotype data thực, không phải chỉ variant list rỗng hoặc summary file.
- Nếu dùng OpenCRAVAT, file nên là TSV/tab-delimited 23andMe-style hoặc VCF chuẩn.

Thứ tự ưu tiên mock input:

1. 23andMe raw data chuẩn build37/hg19, tab-delimited, có header gốc của 23andMe.
2. AncestryDNA raw data chuẩn nếu converter đã installed.
3. VCF GRCh37 hoặc GRCh38 chuẩn, có `REF/ALT` rõ, nếu mục tiêu là pipeline bioinformatics sạch.
4. Kaggle/PGP CSV chỉ nên dùng sau khi đã có preprocessing converter riêng, vì dễ vướng delimiter/header/build.

Với MVP hiện tại, `rsID` vẫn là input backbone thực dụng nhất cho user phổ thông. Nhưng pipeline cần preserve build/position/genotype để audit, convert sang `avinput`/coordinate khi chạy ANNOVAR, và join genotype ngược lại sau InterVar classification.
